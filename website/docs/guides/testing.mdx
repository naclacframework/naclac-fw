Naclac's test workflow uses TypeScript with ts-mocha and the auto-generated client SDK to write end-to-end integration tests against your program running on a local validator. Your tests call real instructions, fetch real account state, and capture real program events — all against a live (local) Solana runtime, with zero mocking required.

## Test Setup

Before running tests, make sure the following prerequisites are in place:

1. **Build your program.** Run `naclac build` to compile the latest `.so` binary and regenerate the TypeScript client in `clients/src/generated/`.

2. **Start a local validator.** In a separate terminal, launch:
   ```bash
   solana-test-validator
   ```
   Keep this process running for the duration of your test session. Naclac targets `http://127.0.0.1:8899` when your `Naclac.toml` sets `cluster = "localnet"`.

3. **Fund your test wallet.** If this is a fresh validator, airdrop some SOL to the wallet configured in `Naclac.toml`:
   ```bash
   naclac airdrop 2
   ```

4. **Install TypeScript dependencies.** Your generated workspace includes a `package.json`. Run your package manager's install command once:
   ```bash
   yarn install
   ```

## Running Tests

### Run all tests

```bash
naclac test
```

Naclac reads the `[scripts] test` command from `Naclac.toml`, sets `TS_NODE_TRANSPILE_ONLY=1`, and executes the script from the workspace root. All test files matching the configured glob (default: `tests/**/*.ts`) are discovered and executed.

### Run a specific test file

```bash
naclac test my_counter.test.ts
```

Naclac injects the target file path into the configured test command, replacing the default glob. You can pass either a bare filename (`my_counter.test.ts`) or a path relative to the workspace root (`tests/my_counter.test.ts`) — Naclac normalises both.

### Build, deploy, then test in one step

```bash
naclac test --all
```

The `--all` flag runs `naclac build` and `naclac deploy` automatically before executing your test suite:

1. `naclac build` — recompiles all programs and regenerates the client SDK
2. `naclac deploy` — deploys the freshly built `.so` binaries to the configured cluster
3. Runs your test script

Use `--all` in CI or whenever you need a clean end-to-end verification from source to on-chain.

## Test Script Configuration

Naclac looks for a `[scripts]` section in `Naclac.toml` to find the test command to run. You can customise this to match your project's toolchain:

```toml
[scripts]
test = "yarn run ts-mocha -p ./tsconfig.json -t 1000000 \"tests/**/*.ts\""
```

| Key | Purpose |
|---|---|
| `test` | The shell command Naclac executes when you run `naclac test` |

The `-t 1000000` flag sets the mocha timeout to 1,000,000 ms (about 16 minutes), giving Solana transactions plenty of time to confirm on a congested devnet. Lower this value when running against a local validator where blocks are near-instant.

If you want to swap ts-mocha for a different test runner (e.g. vitest), update the `test` value accordingly — Naclac passes it verbatim to the shell.

## Writing Tests with the Generated Client

After `naclac build`, Naclac generates a typed TypeScript client in `clients/src/generated/<program_name>.ts`. Import this client in your test files to interact with your program without writing raw transaction builders.

Below is a complete, working test file for a counter program:

```typescript
import * as naclac from "@naclac-fw/client";
import { MyCounterClient } from "../clients/src/generated/my_counter";

describe("Counter Test Suite", () => {
  let client: MyCounterClient;
  let payer: naclac.KeyPairSigner;
  let counterPda: naclac.Address;

  before(async () => {
    payer = await naclac.loadNodeWallet();
    client = new MyCounterClient("localnet", payer);
    counterPda = await client.getCounterAccountPda({});
  });

  it("initializes the counter", async () => {
    try {
      await client.fetchCounter(counterPda);
      console.log("Counter already exists, skipping init.");
    } catch {
      await client
        .initialize({})
        .accounts({ payer: payer.address, counterAccount: counterPda })
        .rpc()
        .catch(naclac.logError);
    }
  });

  it("increments and emits an event", async () => {
    const before = await client.fetchCounter(counterPda);
    const startCount = Number(before.count);

    // Subscribe to event BEFORE sending the transaction
    const eventPromise = client.waitForCounterIncremented({ timeoutMs: 10000 });

    await client
      .increment({})
      .accounts({ authority: payer.address, counterAccount: counterPda })
      .rpc()
      .catch(naclac.logError);

    const after = await client.fetchCounter(counterPda);
    if (Number(after.count) !== startCount + 1) {
      throw new Error("Count did not increment");
    }

    const event = await eventPromise;
    if (!event) throw new Error("Event not captured");
    console.log("Event newCount:", event.newCount);
  });
});
```

Key patterns to note:

- **`naclac.loadNodeWallet()`** loads the keypair from the path set in `Naclac.toml` (default: `~/.config/solana/id.json`).
- **`new MyCounterClient("localnet", payer)`** creates a client bound to the local validator RPC.
- **`.accounts({...}).rpc()`** builds and sends the transaction in one call.
- **Subscribe to events *before* the transaction** — `waitForCounterIncremented` opens a WebSocket subscription that must be active before the transaction lands.

## Fetching Accounts Directly

Use the generated `fetch<AccountName>` method to read on-chain account data after a transaction:

```typescript
const counterData = await client.fetchCounter(counterPda);
console.log("Current count:", Number(counterData.count));
```

The returned object is fully typed based on your program's account definition — field names and types match exactly what you defined in your Naclac program. If the account does not exist, `fetchCounter` throws, which you can catch to detect uninitialized state (as shown in the "initializes the counter" test above).

## Using `naclac.logError`

Pass `naclac.logError` as a `.catch()` handler on any `.rpc()` call to get structured error output:

```typescript
await client
  .increment({})
  .accounts({ authority: payer.address, counterAccount: counterPda })
  .rpc()
  .catch(naclac.logError);
```

When a transaction fails, `logError` extracts the error message, program logs, and simulation output from the RPC response and prints them in a readable format. Without it, the raw RPC error object is often difficult to interpret — especially for custom program error codes.

<Tip>
  Naclac automatically sets the `TS_NODE_TRANSPILE_ONLY=1` environment variable before running your test script. This tells `ts-node` to skip TypeScript type-checking during execution, which significantly speeds up test startup time — especially in larger workspaces. Type errors are caught during development in your editor; this flag keeps the feedback loop fast at test time.
</Tip>

<Note>
  Tests use the wallet keypair configured in `Naclac.toml` under `[provider] wallet` (default: `~/.config/solana/id.json`). This same keypair signs all transactions during the test run and pays transaction fees. On localnet, run `naclac airdrop <amount>` to fund it. On devnet, run `naclac airdrop 2` — the Solana devnet faucet is capped at 2 SOL per request.
</Note>
