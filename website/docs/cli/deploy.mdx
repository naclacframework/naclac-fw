`naclac deploy` takes the compiled `.so` binaries in `target/deploy/` and uploads them to the Solana cluster configured in your `Naclac.toml`. It resolves the target cluster URL and wallet keypair from configuration, then calls `solana program deploy` for each program. Run [`naclac build`](/cli/build) before deploying to ensure the binaries are up to date.

## Usage

```bash
naclac deploy [program_id]
```

## Arguments

| Argument | Description |
|---|---|
| `[program_id]` | Name of a specific program to deploy (e.g., `my_counter`). If omitted, every `.so` file found in `target/deploy/` is deployed. |

## Cluster Configuration

`naclac deploy` reads cluster and wallet settings from the `[provider]` section of your `Naclac.toml`:

```toml
[provider]
cluster = "devnet"
wallet = "~/.config/solana/id.json"
```

Set `cluster` to a named shorthand or paste in a full RPC URL for a private node. The `wallet` field supports `~` expansion to your home directory.

## Examples

```bash
# Deploy all programs in the workspace
naclac deploy

# Deploy a single program by name
naclac deploy my_counter
```

## Supported Clusters

| Value | RPC URL |
|---|---|
| `localnet` | http://127.0.0.1:8899 |
| `devnet` | https://api.devnet.solana.com |
| `testnet` | https://api.testnet.solana.com |
| `mainnet` | https://api.mainnet-beta.solana.com |
| Custom URL | Used directly (e.g., QuickNode/Helius endpoints) |

Any value that does not match a known shorthand is treated as a raw RPC URL and passed directly to the Solana CLI. This lets you use private RPC endpoints from providers like QuickNode or Helius by pasting the full URL into `Naclac.toml`.

## Prerequisites

Run `naclac build` before deploying. If `target/deploy/` does not exist or contains no `.so` files, `naclac deploy` exits with an error.

<Note>
  **Resuming interrupted deployments:** Large programs are uploaded in chunks. If a deployment fails partway through a network interruption or timeout, simply run `naclac deploy` again. The underlying `solana program deploy` command detects the existing buffer account associated with your wallet and keypair and resumes the upload from where it left off rather than starting over.
</Note>
