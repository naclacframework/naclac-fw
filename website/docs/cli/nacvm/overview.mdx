`nacvm` is Naclac's dedicated version manager. It lets you install multiple versions of the `naclac` CLI side by side and switch between them per project or globally — so you always build against the exact framework version your code expects.

## Installing nacvm

Run the one-line installer to download and install `nacvm` on your machine:

```bash
curl -sSfL https://raw.githubusercontent.com/naclacframework/naclac-fw/main/.github/scripts/install-nacvm.sh | sh
```

The script auto-detects your OS and architecture, downloads the correct pre-compiled binary from GitHub Releases, and places it at `$HOME/.nacvm/bin/nacvm`.

The installer also attempts to append the export line to your shell profile (`.zshrc`, `.bashrc`, or `.profile`) automatically. If it does not, add it manually:

```bash
export PATH="$PATH:$HOME/.nacvm/bin"
```

Then reload your shell or source the profile file, and verify the installation:

```bash
nacvm --version
```

You should see the installed `nacvm` version printed to stdout.

## Quick Start with nacvm

Once `nacvm` is on your PATH, install and activate a `naclac` version in three steps:

```bash
# Install the latest stable version
nacvm install latest

# Or install a specific version
nacvm install v0.1.0

# Switch to that version
nacvm use v0.1.0

# Verify the active naclac binary
naclac --version
```

`nacvm install` downloads the correct pre-compiled `naclac` binary for your platform and stores it under `$HOME/.nacvm/versions/<version>/bin/`. `nacvm use` then points the active symlink at that binary so every subsequent `naclac` invocation uses it.

## Why Use nacvm

### Lock a workspace to a specific version

Different Naclac projects may depend on different CLI versions. With `nacvm` you install the exact version each project needs and switch to it before building — no global reinstalls, no version drift.

### Test against multiple versions

Keep several versions installed simultaneously and switch between them in seconds. This makes it easy to reproduce issues reported against older releases or validate that your program compiles correctly after a framework upgrade.

### Upgrade safely with easy rollback

Install a new release with `nacvm install <version>`, try it out, and roll back to the previous version with a single `nacvm use <previous-version>` command if something breaks. Because `nacvm` never deletes a version automatically, your previous binaries are always available until you explicitly uninstall them.

## nacvm vs Direct Install

Naclac also ships a standalone install script (`install.sh`) for users who only need one version of the CLI. Understanding the difference helps you choose the right approach:

| | Direct install (`install.sh`) | nacvm |
|---|---|---|
| **Binary location** | `$HOME/.local/share/naclac/bin/` | `$HOME/.nacvm/versions/<ver>/bin/` |
| **Active binary** | The single installed binary | Symlink at `$HOME/.nacvm/bin/naclac` |
| **Multiple versions** | ✗ One version at a time | ✓ Unlimited versions stored |
| **Version switching** | Requires re-running the script | `nacvm use <version>` |
| **Rollback** | Re-download old release manually | `nacvm use <previous>` |

Use the direct install if you only ever need the latest stable release and want the simplest setup. Use `nacvm` if you work on multiple projects, contribute to Naclac itself, or want fine-grained control over upgrades.
