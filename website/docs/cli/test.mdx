`naclac test` runs the TypeScript integration test suite defined in your workspace's `tests/` directory. It executes the test script configured in `Naclac.toml`, which by default uses `ts-mocha` with a generous timeout suitable for on-chain operations. Use the `--all` flag to run a complete build, deploy, and test sequence in one command.

## Usage

```bash
naclac test [file] [--all]
```

## Flags

| Flag | Description |
|---|---|
| `[file]` | Optional path to a specific test file to run (e.g., `my_counter.test.ts`). If omitted, the test script glob (`tests/**/*.ts`) matches all test files. |
| `--all` | Build all programs, deploy them to the configured cluster, and then run the full test suite in sequence. Equivalent to running `naclac build && naclac deploy && naclac test`. |

## Examples

```bash
# Run all tests using the configured test script
naclac test

# Run a single test file
naclac test my_counter.test.ts

# Build, deploy, and test in one command
naclac test --all
```

## Configuring the Test Script

The test command executed by `naclac test` is read from the `[scripts]` table in `Naclac.toml`. The default generated by `naclac init` is:

```toml
[scripts]
test = "yarn run ts-mocha -p ./tsconfig.json -t 1000000 \"tests/**/*.ts\""
```

Customize this value to change the test runner, adjust the timeout (the `-t` flag, in milliseconds), or target a different file pattern. When you pass a `[file]` argument to `naclac test`, the CLI appends the filename to the script so that only the matching file is executed.

<Note>
  `naclac test` automatically sets the `TS_NODE_TRANSPILE_ONLY=1` environment variable before invoking the test script. This instructs `ts-node` to skip TypeScript type-checking during transpilation, significantly reducing test startup time. Type errors are not caught at runtime — run `tsc --noEmit` separately if you want a full type-check pass before committing.
</Note>
