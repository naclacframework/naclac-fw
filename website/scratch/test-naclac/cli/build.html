naclac build — Compile Programs and Generate IDL

naclac build compiles your Naclac program to SBF bytecode, auto-syncs program IDs, generates the IDL JSON, TypeScript types, and runs naclac generate.

naclac build is the single command that takes your Rust source to a fully-integrated, client-ready program. It compiles every program in the workspace (or a single named program) to SBF bytecode, ensures your program ID is consistent across all configuration files, produces the IDL JSON that describes your program's interface, emits TypeScript types, and then calls naclac generate to produce a ready-to-use TypeScript client SDK — all in one step.

Usage

Copy
naclac build [program_id] [--features <features>]

Arguments and Flags

ArgumentDescription
[program_id]Name of a specific program to build (matches the directory name under programs/). If omitted, all programs in the workspace are built.
--features <features>Comma-separated list of additional Cargo feature flags to pass to cargo build-sbf. Can be specified multiple times.

What naclac build Does

naclac build orchestrates the following steps in order:

  1. Locates the workspace root by searching for Naclac.toml in the current directory or up to two levels above it. Exits with an error if not found.

  2. Verifies or generates the program keypair in target/deploy/<name>-keypair.json. If the keypair file does not exist, it calls solana-keygen new to create one automatically.

  3. Auto-syncs the program ID in both programs/<name>/src/lib.rs (the declare_id! macro argument) and Naclac.toml (under [programs.<cluster>]) to match the public key derived from the keypair on disk. This keeps all three sources of truth in lock-step without manual editing.

  4. Detects the execution mode by inspecting the program's Cargo.toml. If a pinocchio feature is declared, the build passes --no-default-features --features pinocchio to cargo build-sbf, producing a no_std binary. If idl-build is declared, it is injected to enable on-chain IDL instruction embedding.

  5. Runs cargo build-sbf with the resolved feature flags, compiling the program to a .so binary placed in target/deploy/.

  6. Generates the IDL JSON by invoking the internal naclac-idl library against the parsed program source. The IDL captures all instructions, accounts, events, and errors. It is written to target/idl/<name>.json.

  7. Generates TypeScript types from the IDL using naclac-client-gen, writing a .ts types file to target/types/<name>.ts.

  8. Runs naclac generate automatically as a final step, reading the freshly-written IDL and producing the full TypeScript client SDK at clients/src/generated/<name>.ts.

Examples

Copy
# Build all programs in the workspace
naclac build

# Build a single named program
naclac build my_counter

# Build with an extra Cargo feature flag
naclac build my_counter --features debug-mode

# Build with multiple feature flags
naclac build my_counter --features debug-mode --features verbose-logs

Program ID auto-sync: If you delete target/deploy/ and let naclac build regenerate your keypairs, a new program ID is derived from the new keypair. The build step automatically updates declare_id! in lib.rs and the program address in Naclac.toml to match, so you never have to copy-paste a program ID manually. After the sync, re-deploy to register the new address on-chain.
