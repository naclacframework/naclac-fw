Naclac CLI — Utility and Management Commands Guide

Reference for naclac doctor, clean, airdrop, logs, expand, profile, account, idl, and add commands for workspace and environment management.

Naclac includes several utility commands beyond the core build/deploy/test workflow. Use them to verify your environment, manage build artifacts, fund wallets on test networks, debug macro expansion, profile compute usage, and inspect on-chain state.

naclac doctor

naclac doctor checks that every tool Naclac depends on is installed and callable. Run it whenever you set up a new machine, after updating your Solana toolchain, or when a build command fails with an unexpected error.

Copy
naclac doctor

The command probes the following dependencies in order and prints a ✅ or ❌ next to each:

CheckCommand probed
Naclac CLI Router (SBF builder)cargo-build-sbf --version
Rust Compilerrustc --version
Solana CLIsolana --version
Node.jsnode --version
Yarn Package Manageryarn --version

If all checks pass, the output ends with:

Copy
🎉 Your environment is perfectly configured for Naclac!

If any check fails, the output lists the missing tools and advises you to install them before proceeding. Install missing items from their official sources: Rust, Solana CLI, and Yarn.

naclac clean

naclac clean removes build artifacts from target/ to free disk space or force a clean rebuild. The default (soft) clean deliberately preserves your program keypairs so you do not accidentally regenerate new program IDs.

Copy
# Soft clean — removes compiled artifacts but preserves keypairs in target/deploy/
naclac clean

# Hard clean — deletes everything, including program keypairs
naclac clean --hard

Soft clean behaviour: All subdirectories of target/ are removed except target/deploy/*.json (your keypair files). The .anchor/ directory is also removed. This is safe to run at any time — your deployed program IDs are preserved.

Hard clean behaviour: The entire target/ directory is deleted along with node_modules/, dist/, and .anchor/. You are prompted to confirm before anything is deleted. The deletion runs on a background thread with a live spinner; press Ctrl+C to abort and the CLI will attempt to restore any files it has not yet deleted.

naclac clean --hard permanently deletes your program keypairs in target/deploy/. If you have already deployed to devnet or mainnet under those keypair addresses, you will lose the ability to upgrade those programs after deletion. Only use --hard if you intentionally want to regenerate your program IDs.

naclac airdrop

naclac airdrop requests an airdrop of SOL to the wallet configured in Naclac.toml. Use it to fund your development wallet on localnet or devnet without leaving the terminal.

Copy
# Airdrop the default amount (1 SOL)
naclac airdrop

# Airdrop a specific amount
naclac airdrop 5

The amount argument accepts a decimal value (e.g., naclac airdrop 0.5). If omitted, it defaults to 1.0 SOL.

Airdrops are only available on localnet and devnet. Attempting an airdrop on testnet or mainnet will be rejected by the RPC node.

naclac logs

naclac logs tails the transaction logs from the cluster configured in Naclac.toml. Use it to watch program output and error messages in real time during development or debugging.

Copy
# Tail all logs from the cluster
naclac logs

# Filter logs to a specific program
naclac logs my_counter

When you pass a program name, only log lines emitted by that program ID are shown. This is especially useful on a busy localnet where multiple programs are generating output simultaneously.

naclac expand

naclac expand runs cargo-expand on your program to show the fully expanded Rust code after all macros have been applied. Use it to understand exactly what code Naclac macros generate, or to debug a macro-related compilation error.

Copy
# Expand all programs in the workspace
naclac expand

# Expand a specific program
naclac expand my_counter

# Expand with additional feature flags
naclac expand my_counter --features pinocchio

The output is the complete, human-readable Rust source with all macro_rules! and proc-macros inlined. Pipe it to a file or a pager for easier reading:

Copy
naclac expand my_counter > expanded.rs

cargo-expand must be installed on your system (cargo install cargo-expand) and rustfmt must be available for formatted output.

naclac profile

naclac profile runs your test suite and reports the compute unit (CU) consumption of each instruction call. Use it to identify instructions that are approaching the 200,000 CU per-transaction limit and need optimization.

Copy
# Profile compute unit usage across all tests
naclac profile

# Profile a specific test file
naclac profile my_counter.test.ts

After the test run completes, naclac profile summarises CU usage per instruction, showing you the minimum, maximum, and average compute consumed across all test invocations. This gives you a concrete baseline before and after optimization work.

naclac account

naclac account fetches an on-chain account by address, deserializes its data using your local IDL, and prints a human-readable representation of the account fields.

Copy
naclac account <ADDRESS>

Replace <ADDRESS> with the base58-encoded public key of the account you want to inspect. The CLI resolves the RPC endpoint from your active Solana CLI configuration at ~/.config/solana/cli/config.yml, so it queries whichever cluster you have set with solana config set --url.

This is faster than writing a one-off script to fetch and log account data during development. If the account's discriminator does not match any type in the local IDL, the raw bytes are printed instead.

naclac idl init

naclac idl init uploads your program's IDL JSON to a dedicated on-chain account associated with the program. Storing the IDL on-chain makes your program discoverable to off-chain clients and explorers that can fetch the IDL directly from the network without needing local files.

Copy
# Upload IDL for all programs
naclac idl init

# Upload IDL for a specific program
naclac idl init my_counter

Run naclac build first to ensure target/idl/<name>.json is up to date before uploading. Re-run naclac idl init after any build that changes your program's interface to keep the on-chain IDL in sync.

naclac add

naclac add adds a new program to an existing Naclac workspace. It generates the program source tree, registers the program in Naclac.toml, creates a new keypair, and scaffolds a TypeScript test file — the same steps naclac init performs for a single program, but applied to a workspace that already exists.

Copy
# Add a new program with interactive mode selection
naclac add my_new_program

# Add a new program with an explicit mode
naclac add my_new_program --mode pinocchio

--mode accepts the same values as naclac init: pinocchio, standard, or optimized. If omitted, an interactive prompt appears.

Run this from the workspace root (where Naclac.toml lives). The new program directory is created at programs/my_new_program/ and the workspace Cargo.toml members array is updated automatically.
