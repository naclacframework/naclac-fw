Core Concepts

Naclac Workspace Layout and Naclac.toml Configuration

Understand the Naclac workspace directory layout, the role of Naclac.toml, and how to configure clusters, wallets, and test scripts.

When you run naclac init <name>, Naclac scaffolds a full multi-tool workspace that wires together your Rust program crate, a generated TypeScript client, an integration test suite, and deployment configuration in one coherent directory tree. Understanding this layout helps you navigate the project confidently, add programs cleanly, and customize the build pipeline without breaking the toolchain's assumptions.

Directory Layout

The tree below shows what a freshly initialized workspace named my_workspace looks like, along with the purpose of each file and folder.

Copy
my_workspace/
├── Naclac.toml              # workspace config (cluster, wallet, scripts)
├── Cargo.toml               # Rust workspace manifest
├── package.json             # Node.js deps (@naclac-fw/client, ts-mocha)
├── tsconfig.json            # TypeScript config
├── programs/
│   └── my_counter/
│       ├── Cargo.toml       # program crate (features: pinocchio / borsh / zero-copy)
│       └── src/
│           ├── lib.rs               # #[naclac_program] entry point
│           ├── components/          # #[component] data structs
│           ├── instructions/        # #[instruction] handlers
│           ├── systems/             # pure business logic helpers (#[system])
│           ├── events.rs            # #[event] structs
│           ├── errors.rs            # #[error_code] enums
│           └── constants.rs         # const byte seeds
├── tests/
│   └── my_counter.test.ts   # TypeScript integration test
└── target/
    ├── deploy/              # compiled .so binaries + keypairs
    ├── idl/                 # generated IDL JSON files
    └── types/               # generated TypeScript type files

Key directories explained

PathWhat goes here
programs/<name>/src/lib.rsThe #[naclac_program] macro entry point. Naclac reads this file to discover all instructions, components, and events.
programs/<name>/src/components/One file per #[component] struct. Each struct represents an on-chain account layout.
programs/<name>/src/instructions/One file per #[instruction] handler. Each file declares the accounts context and the instruction logic.
programs/<name>/src/systems/Pure Rust functions annotated with #[system]. These hold reusable business logic that instructions delegate to. They are never exported to the IDL.
programs/<name>/src/events.rs#[event] structs emitted via emit!(). Naclac encodes these into the IDL so the TypeScript client can subscribe to them.
programs/<name>/src/errors.rs#[error_code] enums. Custom program error codes that map to descriptive messages in the IDL.
programs/<name>/src/constants.rsconst byte arrays used as PDA seeds. Define seeds here so both Rust and the generated TypeScript client reference the same values.
target/deploy/Compiled .so binaries and their corresponding <name>-keypair.json files. Never commit keypair files for mainnet programs.
target/idl/One <name>.json IDL file per program, regenerated on every naclac build.
target/types/Raw TypeScript type definitions derived from the IDL, consumed internally by the generated client.

Naclac.toml Reference

Naclac.toml is the single source of truth for workspace-level configuration. It lives at the root of your workspace and is read by the naclac CLI for every command.

Copy
[toolchain]
package_manager = "yarn"

[features]
resolution = true
skip-lint = false

[programs.localnet]
my_counter = "<PROGRAM_ID>"

[provider]
cluster = "localnet"
wallet = "~/.config/solana/id.json"

[scripts]
test = "yarn run ts-mocha -p ./tsconfig.json -t 1000000 \"tests/**/*.ts\""

[toolchain]

KeyTypeDescription
package_manager"yarn" | "npm" | "pnpm"The Node.js package manager Naclac uses when installing JavaScript dependencies and running scripts. Defaults to "yarn".

[features]

KeyTypeDescription
resolutionboolWhen true, Naclac adds a resolutions field to package.json to pin @naclac-fw/client sub-dependencies. Useful for preventing version drift in yarn workspaces.
skip-lintboolWhen true, naclac build skips the Rust clippy pass. Set to true if you want faster iteration builds during active development, but keep false in CI.

[programs.<cluster>]

Defines the program ID for each deployment target. The key is the program name (matching the crate name in Cargo.toml) and the value is the base-58 program ID.

Copy
[programs.localnet]
my_counter = "CounterAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAAA"

[programs.devnet]
my_counter = "CounterBBBBBBBBBBBBBBBBBBBBBBBBBBBBBBBBBBBBB"

[programs.mainnet]
my_counter = "CounterCCCCCCCCCCCCCCCCCCCCCCCCCCCCCCCCCCCCCC"

Naclac injects the correct program ID into the compiled binary based on the [provider] cluster value at build time. To deploy to a different cluster, update [provider] cluster and run naclac build again.

[provider]

KeyTypeDescription
clusterstringThe target Solana cluster. See Cluster Values below.
walletstringPath to the deployer wallet keypair file. Supports ~ expansion. This wallet pays for deployments and is the default payer in local tests.

[scripts]

Arbitrary named scripts executed by naclac run <name>. The test key is special — naclac test invokes it automatically after starting a local validator and deploying your programs.

Copy
[scripts]
test = "yarn run ts-mocha -p ./tsconfig.json -t 1000000 \"tests/**/*.ts\""
migrate = "yarn run ts-node scripts/migrate.ts"

Cluster Values

Set cluster in [provider] to any of the following:

ValueEndpoint
"localnet"http://127.0.0.1:8899 — spins up solana-test-validator automatically when you run naclac test.
"devnet"https://api.devnet.solana.com
"testnet"https://api.testnet.solana.com
"mainnet"https://api.mainnet-beta.solana.com
Custom URLAny fully-qualified HTTPS or WSS RPC endpoint, e.g. "https://my-node.quiknode.pro/abc123/". Use this for private RPC providers such as QuickNode or Helius to avoid rate limits in CI.

When you set a custom RPC URL, naclac test does not start a local validator — it connects directly to the specified endpoint. Make sure your wallet is funded on that cluster before deploying.

Adding a Program

To add a second program to an existing workspace, run:

Copy
naclac add <program_name>

This command:

  1. Creates programs/<program_name>/ with the full src/ scaffold.
  2. Adds the new crate to the root Cargo.toml workspace members array.
  3. Adds a [programs.localnet] entry with a freshly generated program ID to Naclac.toml.
  4. Creates tests/<program_name>.test.ts with a minimal test stub.

After adding a program, run naclac build to compile it and generate its IDL and TypeScript client alongside your existing programs.
